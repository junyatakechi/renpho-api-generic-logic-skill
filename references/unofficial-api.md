# 非公式APIが壊れたとき

## 扱うこと

APIが失敗したとき・応答の形が変わったとき、失敗をどう見分け、どこを見て直すか

## 答え方と理由

### 0. 判断全体

RENPHOが公式APIを出していないときに、次のとおりにする。

### 1. 叩いているのは、予告なく壊れる内部APIと読む

RENPHOに公式APIは無い。叩いているのはRENPHO Healthアプリの内部APIで、仕様は公開されておらず、予告なく壊れる。

1. （知見）RENPHOは公式APIを公開していない。（出典：なし）
2. （原因）旧ホストから現行ホストへ移ったときと、2026-10 のログインの変更（答え方5の理由）で、少なくとも2回壊れている。（発生日：記録なし）

### 2. 旧ホストには戻さない

旧ホスト（`renpho.qnclouds.com`）には戻さない。旧Renphoアプリ専用で、RENPHO Healthのアカウントでは動かない。

1. （知見）旧ホスト（sign_in → list_scale_user → measurements/list）は旧Renphoアプリ専用で、RENPHO Healthのアカウントでは動かない。参照実装（hass_renpho など）も更新が止まり、レート制限やIPの遮断の報告がある。現行の `cloud.renpho.com` が、RENPHO Health（青いアイコン）のアカウント用。（出典：なし）

### 3. 壊れたら、同じプロトコルを追う実装との差分を見る

壊れたら、同じプロトコルを追っている次の実装との差分を見る。どれも依存には入れず、仕様の参照先として使う。Issue に、先に踏んだ人の報告と回避策が出ていることが多い。

- `danvaneijck/renpho-api`（PyPI `renpho-api`）：最も追従が早い
- `forkerer/RenphoGarminSync-CLI`：元のリバースエンジニアリング
- `StartupBros-com/renpho-mcp-server`

1. （原因）答え方5の破損の回避策は、`danvaneijck/renpho-api` の Issue #12・#10 にあった。本体のコードはまだ直っていなかった。（発生日：2026-10-23）
2. 記録なし

### 4. 差分を取り込んだら、道具の定数とこの判断を直す

差分を取り込んだら、`renpho_api.py` の定数とこの判断を直す。呼び出し側には手を入れずに済むようにする。

1. 記録なし

### 5. ログインの拒否と、プロトコルの破損を分ける

`RenphoAuthError` で「ログインに失敗」と出たら、まず認証情報を疑う（[認証情報の扱い](credentials.md)）。正しい認証情報で、復号の失敗・`code=-114`（本文を復号できない）・`code=104`（ユーザー名かパスワードの誤り）・想定外の `code` が続くなら、プロトコルの破損を疑う。`code=104` は、アプリの版が古いときにも返る。Issue の回避策のとおりに `cellphoneType` を `MCP-Server`、`bindingList` を `["2"]` に変えない。アプリの版 7.0.0 がいつまで受け付けられるかは（未決 U1）。

1. （原因）保存済みのtokenが403になったので再ログインしたところ、正しい認証情報で `code=-114` が返った。`msg` は空で、説明文は `message` にあった。ログインの要求に `appVersion`・`platform` のヘッダーを付け、アプリの版を 6.6.0 から 7.0.0 に上げると、`code=101` で通った。2つを同時に直したので、片方だけで通るかは確かめていない。（発生日：2026-10-23）
2. （知見）ヘッダーだけ直して版が 6.6.0 のままだと、`code=104` が返る。（出典：danvaneijck/renpho-api の Issue #12・#10@2026-10-23）
3. （根拠）ヘッダーと版だけで通った。`bindingList` を変えると、返る機器の紐付けが変わるおそれがある。（決定日：2026-10-23）

### 6. ログインが拒否されたら、ログインを繰り返さない

ログインが拒否されたら、ログインを繰り返さない。`renpho_auth.py check` を1回だけ流して `code` と説明文を確かめ、答え方3の差分を見てから試す。

1. （根拠）壊れているうちにログインを繰り返しても、通らない。成功すれば、そのたびにスマホアプリがログアウトされる（[セッションとトークン](session.md)）。（決定日：記録なし）

## 道具

答え方5・6：`uv run <skill-dir>/scripts/renpho_auth.py check` が、`debug=True` で、エンドポイントごとの `code` と説明文を出す。

答え方3・4：`uv run <skill-dir>/scripts/probe_fields.py --json <保存先>` で、応答の形が変わっていないかを、全件で確かめる。

道具の中に実装してあること：ログインを含むすべての要求に `appVersion`・`platform` のヘッダーを付ける。説明文は `msg` が無ければ `message` から読む。成功は `code` の 0・200・101 か、説明文の `success` で見分ける。

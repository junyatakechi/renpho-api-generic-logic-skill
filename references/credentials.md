# 認証情報の扱い

## 扱うこと

認証情報を設定する・疎通を確かめるとき、パスワード本体を、どこに、誰が書くか

## 答え方と理由

### 0. 判断全体

RENPHO Health がメールアドレスとパスワードでしかログインできないときに、次のとおりにする。`RenphoAuthError` がどの設定の不足によるかは、この判断では答えない（→ [設定の不足](missing-setup.md)）。

### 1. `.env` には、パスワード本体が入る

`.env` には、RENPHOアカウントのパスワード本体が入る。他のサービスと使い回していないパスワードにしてもらう。

1. （知見）RENPHO Healthのログインはメールアドレスとパスワードだけで、OAuthのリフレッシュトークンのような、トークンを発行する別の経路が無い。（出典：なし）

### 2. Claudeはパスワードを受け取らない

Claudeはパスワードを受け取らない。雛形だけを作り、値は利用者が自分でエディタに書き込む。チャットでパスワードを聞かない・貼られても書き込まない。`init` でメールアドレスとパスワードを引数で受け取らない。

1. （根拠）Claudeにパスワードを渡さない。（決定日：記録なし）

### 3. 認証情報はスキルの外に置く

認証情報はスキルの外に置く。プロジェクトのフォルダ直下（起動フォルダ）の `.env`。プロジェクトのスキルと共有するので、道具は `RENPHO_*` の行だけを書き換える。スキルのフォルダには実値を置かない。

1. 記録なし

### 4. 暗号化の鍵を、秘密として扱わない

リクエストの暗号化の鍵は秘密ではない。アプリに埋め込まれた固定値で、複数のリバースエンジニアリング実装が同じ値を公開している。難読化であって、通信を守る仕組みではない。秘密として扱って隠す必要も、守られていると見なす根拠も無い。

1. （知見）`danvaneijck/renpho-api` などが、同じ鍵を載せている。（出典：danvaneijck/renpho-api@記録なし）

### 5. 取れるのは、ログインしたアカウント自身の測定だけ

取れるのは、ログインしたアカウント自身の測定だけ。家族メンバーの測定は対象外。

1. 記録なし

## 道具

答え方2：`uv run <skill-dir>/scripts/renpho_auth.py init` が、雛形を作り、書き込む手順を案内する。メールアドレス・パスワードは受け取らない。

答え方3：保存は `renpho_env.write` / `save_session` が行い、作れる環境ではファイルを所有者だけが読み書きできる権限（600）に絞る。同じキーの環境変数があれば、読むときはそちらを優先する。`RENPHO_TOKEN`・`RENPHO_USER_ID` は道具が書き戻すので、環境変数で渡さず `.env` に置く。

疎通の確認：`uv run <skill-dir>/scripts/renpho_auth.py check`。保存済みtokenがあればログインしない（[セッションとトークン](session.md)）。

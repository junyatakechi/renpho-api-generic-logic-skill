# セッションとトークン

## 扱うこと

RENPHOに接続するコードを書く・同期を呼ぶ頻度を決めるとき、ログインでアプリが落ちるのをどう最小にするか

## 答え方と理由

### 0. 判断全体

RENPHO Health（`cloud.renpho.com`）のアカウントについて、次のとおりにする。

- （原因）実装当初は、同期のたびにログインしていたため、そのたびに対象者のスマホアプリが強制ログアウトされていた。（発生日：記録なし）
- （知見）2回ログインすると、tokenは毎回異なり、1回目のtokenは即座に無効化されて403になる。tokenだけ（パスワード無し）で叩けるので、キャッシュが成立する。tokenの有効期限は、JWTの `exp` で90日（`exp` = `iat` + 90日）。（実測：2026-08-12〜2026-08-12・件数は記録なし）

### 1. ログインは最後の手段にし、保存済みのtokenで叩く

ログインは最後の手段。保存済みのtokenで叩く。`RenphoClient.login()` を直接呼ばず、`ensure_auth()` を使う。保存済みtokenがあればログインしない。同期のたびにログインしない。

1. 答え方0の理由と同じ。

### 2. ログインしたら、tokenを必ず保存する

ログインしたら、tokenを必ず保存する。`on_login` で永続化する。

1. （根拠）保存を怠ると次回もログインが走り、そのたびにアプリがログアウトされる。（決定日：記録なし）

### 3. tokenが403になったら、一度だけ再ログインし、ログに出す

tokenが403になったら、一度だけ再ログインする。同期は失敗させない。ただし再ログインしたことは必ずログに出す。

1. （根拠）再ログインには、アプリのセッションが切れる副作用がある。（決定日：記録なし）
2. （知見）403はHTTPのステータスではなく、本文の `code` で返る（HTTPは200のまま）。（実測：2026-08-12〜2026-08-12・件数は記録なし）

### 4. 端末情報を変えて回避しようとしない

端末情報（`platform`/`cellphoneType`/`systemType`）を変えて、アプリと別のセッション枠をもらおうとしない。同じ実験を繰り返さない。

1. （知見）`platform: ios` を名乗ってログインしても、直前のandroid名乗りのtokenが403になった。セッションはuserId単体で管理されている。（実測：2026-08-12〜2026-08-12・件数は記録なし）

### 5. 繰り返し呼ばれる同期では、接続の前に記録先の鮮度を見る

繰り返し呼ばれる同期では、接続の前に記録先の鮮度を見る。記録先の最新の測定が十分新しければ、RENPHOに接続すらしない。何時間を「十分新しい」とするかは、呼び出し側が決める。

1. （根拠）評価のたびに同期を呼ぶ使い方では、tokenが生きていても、アプリ側が後からログインしていればこちらは403→再ログインになり、今度はアプリが落ちる。接続そのものを減らすのが最も効く。（決定日：記録なし）

### 6. アプリと共存できないことを、対象者に伝える

アプリとこちらのセッションは、原理的に共存できない。できるのは「ログインの回数を最小にする」ところまで。初めてログインしたとき・tokenの90日の期限が切れたとき・403で再ログインしたときにアプリがログアウトされることは、対象者に伝える。あわせて、アプリでログインし直すまで新しい測定がRENPHOに上がらないこと（[測定がクラウドに上がる時期](upload-timing.md)）と、アプリでログインし直すとこちらのtokenが無効になり、次の同期で再ログインすることも伝える。

1. 答え方4の理由1と同じ。
2. （原因）こちらのログインでアプリがログアウトされたことを伝えていなかったので、対象者がアプリを開かず、8日分の測定がRENPHOに上がらなかった。（発生日：2026-11-18）

## 道具

答え方1〜3：クライアントは `renpho_env.open_client()` から作る。`open_client()` は保存済みtokenを渡し、ログインしたら `.env` へ保存して、標準エラー（または渡した `log`）に「ログインした」と出す。403の再ログインは `renpho_api.RenphoClient._post` が一度だけ行う。呼び出し側は `client.ensure_auth()` を呼んでから取得する。

```python
from renpho_env import open_client
client = open_client(log=print)
client.ensure_auth()
records = client.get_measurements()
```

答え方5：道具で強制できない（記録先を知っているのは呼び出し側）。呼び出し側が、接続の前に記録先の最新の測定時刻を読み、閾値以内なら `open_client()` を呼ばずに終える。

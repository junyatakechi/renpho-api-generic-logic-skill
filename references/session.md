# セッションとトークン

## 求める材料

| 材料 | 種類 | 必須 | 形 | 無いとき |
|---|---|---|---|---|
| RENPHOに接続する目的と頻度（例：評価のたびに呼ばれる同期、手動の一括取り込み） | 対象の属性 | ○ | 文章 | 判断できない |
| 記録先に、最新の測定の時刻を問い合わせられるか | 対象の属性 | — | はい / いいえ | 答え5を省いて答える |

## 答え

1. **ログインは最後の手段。保存済みのtokenで叩く。** `RenphoClient.login()` を直接呼ばず、`ensure_auth()` を使う。保存済みtokenがあればログインしない。
2. **ログインしたら、tokenを必ず保存する。** `on_login` で永続化する。保存を怠ると次回もログインが走り、そのたびにアプリがログアウトされる。
3. **tokenが403になったら、一度だけ再ログインする。** 同期は失敗させない。ただし再ログインしたことは必ずログに出す（アプリのセッションが切れる副作用があるため）。
4. **端末情報（`platform`/`cellphoneType`/`systemType`）を変えて回避しようとしない。** 検証済みで効かない。同じ実験を繰り返さない。
5. **繰り返し呼ばれる同期では、接続の前に記録先の鮮度を見る。** 記録先の最新の測定が十分新しければ、RENPHOに接続すらしない。これが最も効く。何時間を「十分新しい」とするかは呼び出し側が決める。
6. **アプリとこちらのセッションは原理的に共存できない。** できるのは「ログインの回数を最小にする」ところまで。初めてログインしたとき・tokenが切れたときにアプリがログアウトされることは、利用者に伝える。

## 道具

- **クライアントは `renpho_env.open_client()` から作る。** 答え1・2・3は道具の中に実装してある。`open_client()` は保存済みtokenを渡し、ログインしたら環境ファイルへ保存して、標準エラー（または渡した `log`）に「ログインした」と出す。403の再ログインは `renpho_api.RenphoClient._post` が一度だけ行う。
- 呼び出し側は `client.ensure_auth()` を呼んでから取得する。`client.login()` は呼ばない。
- 答え5は道具で強制できない（記録先を知っているのは呼び出し側）。呼び出し側が、接続の前に記録先の最新の測定時刻を読み、閾値以内なら `open_client()` を呼ばずに終える。

```python
from renpho_env import open_client
client = open_client(log=print)
client.ensure_auth()
records = client.get_measurements()
```

## 理由

2026-08-12に実測で確定した。実装当初は、同期のたびにログインしていたため、そのたびに本人のスマホアプリが強制ログアウトされていた。

| 確かめたこと | 結果 |
|---|---|
| 2回ログインしたときのtoken | 毎回異なる。1回目のtokenは**403**になり、即座に無効化される |
| tokenだけ（パスワード無し）で叩けるか | **叩ける。** だからキャッシュが成立する |
| tokenの有効期限 | JWTの `exp` で**90日**（`exp` = `iat` + 90日） |
| 端末情報を変えれば別枠をもらえるか | **もらえない。** `platform: ios` を名乗ってログインしても、直前のandroid名乗りのtokenが403になった。セッションは**userId単体**で管理されている |

- 403はHTTPのステータスではなく、本文の `code` で返る（HTTPは200のまま）。
- 答え5：評価のたびに同期を呼ぶ使い方では、tokenが生きていても、アプリ側が後からログインしていればこちらは403→再ログインになり、今度はアプリが落ちる。接続そのものを減らすしかない。

## 却下した案

| 案 | 理由 |
|---|---|
| 同期のたびにログインする | アプリが毎回ログアウトされる（実装当初に起きていた） |
| 端末情報を変えて、アプリと別のセッション枠をもらう | 検証して効かなかった（理由の表の4行目） |

## 当てはまる範囲と限界

- RENPHO Health（`cloud.renpho.com`）のアカウントで確かめたこと。RENPHOの仕様が変わったら試し直す。
- tokenの90日の期限が切れたときは、ログインが1回走る。避けられない。
